## Summary

Implements the `data-mining-template` specification as the **msys2-dataset**
repository: a DataLad-versioned dataset that pairs MSYS2 and MINGW package
metadata, runnable in four environments (Codespaces, Binder, local uv, DataLad)
with CI for TestPyPI and the HuggingFace Hub.

Delivered over 19 commits using TDD: the contract first as a red `[WIP]` commit,
then implementation commits that turn it green.

## What this adds

**Dataset**

- `data/repo/repo-list.txt` is the single source of truth for upstream
  repositories, and `data/repo/` is backed by **real git submodules**
  (mode-160000 gitlinks + `.gitmodules`) pinned to specific commits:

  | submodule | pin |
  | --- | --- |
  | `data/repo/msys2-packages` | `e555935` |
  | `data/repo/MINGW-packages` | `c70dff2` |

- Pairing the two listings yields **304 paired** packages from 608 MSYS2 and
  3361 MINGW entries — exactly half the MSYS2 set has a MINGW counterpart.

**Storage (`src/msys2_dataset/store.py`)**

A columnar, zstd-partitioned format for large tables: a **plain uncompressed
tar** containing `<table>/<column>.zst.partNN`, with each part an independently
decompressable zstd frame.

- `FAT32_MAX_BYTES = 4 GiB − 1`, enforced against **compressed** size so no
  produced file can break FAT32.
- Table/column names validated against path traversal.

Supporting modules: `io` (CSV/JSONL, zstd, tar.zst), `sqlite_store` (fast-write
fallback), `packages` (listing parser + pairing), `repolist`, `cli`.

**Environments & CI**

- `.devcontainer/` (uv + ruff features, Jupyter) and `.binder/` (git-annex,
  DataLad init).
- `tests.yml` (ruff + pytest on 3.10/3.11/3.12), `publish-testpypi.yml`,
  `sync-huggingface.yml`.
- `requirements.txt` is authoritative; the gitignored `pyproject.toml` is
  generated by `tools/gen_pyproject.py`, and **every** workflow regenerates it
  with that tool rather than inlining a heredoc.

**Notebooks** — `01_exploration` and `02_analysis`, generated by
`tools/make_notebooks.py` and executed by `tools/run_notebooks.py`.

## Bugs found and fixed while making CI green

These are worth a reviewer's attention because each was a real defect, not a
flake. Each is filed as an issue:

1. **PEP 668** ([#3](https://github.com/fufurobot/msys2-dataset/issues/3)) —
   `uv pip install --system` is rejected on Ubuntu 24.04 runners and silently
   targeted the wrong interpreter. Switched to `uv sync` with `UV_PYTHON` pinned.
2. **Ruff drift** ([#3](https://github.com/fufurobot/msys2-dataset/issues/3)) —
   `requirements.txt` pinned ruff 0.4.4 while CI installed 0.16.10; the two
   disagreed about formatting *and* import classification (isort classifies
   first-party by importability, which differs between "installed in venv" and
   "src on PYTHONPATH"). Pinned the version and the isort view.
3. **Submodule check** ([#2](https://github.com/fufurobot/msys2-dataset/issues/2)) —
   `--check` conflated *registration* (a git-index fact, which `repo-list.txt`
   governs) with *checkout* (a working-tree fact). It now fails only on genuine
   registration drift.
4. **FAT32 off-by-one** ([#4](https://github.com/fufurobot/msys2-dataset/issues/4)) —
   the cap is `4 GiB − 1`, since FAT32 stores size in 32 bits.

## Known limitation

[#1](https://github.com/fufurobot/msys2-dataset/issues/1) — git-annex is a system
dependency with no usable Python distribution, and it could not be installed in
this environment (MSYS2 mirrors unreachable). The repository **is** a valid
DataLad dataset (`AnnexRepo`, dataset id `c82f7932-…`), and CI installs
git-annex via apt, but `datalad get .` was not exercised end to end locally.
